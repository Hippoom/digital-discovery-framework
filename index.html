positioning

Discovery 的作用：将业务机会转为受治理的投入判断

Discovery 在机会与解决方案方向之间发散、收敛，以权衡价值、可行性、风险、投入与时机；获 Go 的纲要切片进入 Inception，再通过切片与实现路径的探索收敛为可实施方案。

1

Business Opportunity 多个业务问题、需求或机会进入探索；不同机会会因价值、条件与方案方向而形成不同优先级。

2

Discovery：探索与投入判断 比较多种解决方案方向，包括非 AI 路线、能力组合与 Agent 边界；形成 Solution Hypothesis、Solution Outline 与 Integrated Assessment。

3

Decision Gate 收敛为 Go（通过）/ Defer（暂缓）/ No-go（不推进），明确投入方向、相对优先级、关键条件与时机。

4

Inception → Implementation → Operations 获 Go 的 Outline 切片进入 Inception；比较切片方式与实现路径，收敛为可实施方案，再进入建设、运行、衡量与学习。

当前 renderer 以顺序流程呈现；“探索—收敛—再探索—再收敛”的双菱形模板已记录为 Skill 反馈候选项，待受控语义与主题模板支持后替换。

framework

Workflow、Operating Model 与 Reference 共同让 Discovery 可执行、可治理且判断一致

Workflow 定义决策如何形成，Operating Model 定义谁提供证据、谁作决定，Reference 提供可复用的判断参照。

Workflow

  • 将业务机会逐步转为解决方案假设、纲要、综合评估与决策包。
  • 明确 Discovery 的范围，以及与 Inception 的交接边界。

Operating Model

  • 明确角色、责任、评估输入与决策关口的授权机制。
  • 确保每项关键判断都有证据责任人，每个关口都有正式授权主体。

Reference

  • 提供场景适配、能力边界与判断一致性的参照体系。
  • 支持将业务问题、AI 能力组合与 Agent 边界联系起来。

workflow

Discovery 通过“方向形成—纲要与评估—决策关口”将机会转为正式投入判断

解决方案纲要提出“建议做什么”，综合评估判断“凭什么值得、做得了、管得住、现在该做”；二者共同支撑 Go、Defer 或 No-go。

1. 方向形成

业务机会 → 解决方案假设（Solution Hypothesis）

  • 澄清目标对象、业务情境、价值承诺、初始范围与非目标。
  • 将“想用 AI / Agent”转为可被证据支持或推翻的解决方案方向。

2. 纲要与评估

解决方案纲要（Solution Outline）

  • 方案主张（Proposition）：目标场景、能力与交互方向、行动边界、所需信息与行动、假设与约束。

综合评估（Integrated Assessment）

  • 证据与判断（Evidence & Judgement）：价值与战略、解决方案适配、准备状态、技术、风险与管控、投入与时机。

3. 决策关口

决策包（Decision Package） → Go / Defer / No-go

  • 汇集假设、纲要、评估、关键条件、风险与量级判断。
  • Go（通过）进入 Inception；Defer（暂缓）记录重启条件、责任人和复审触发；No-go（不推进）记录理由与替代路线。
这是逻辑顺序而非瀑布：评估可修正纲要和假设，也可直接支持 Defer 或 No-go。

operating model

RACI 让角色、证据责任与 Decision Gate 的正式授权保持清晰

Solution Lead 整合从机会到决策包的工作；各角色对相应事实和证据负责；Decision Authority 在 Decision Gate 作出正式决定。
