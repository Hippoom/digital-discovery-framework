    Deployment 与 Operational 技术使能¶

    用途：作为 Technology Assessment 下的早期可复用 Assessment Domain，判断 Solution Outline 是否存在可信的 hosting / deployment、runtime / dependency 以及最低 IT Operations 承载、支持与管理路径。

    DFX 对齐：Deployment Viewpoint + Operational Viewpoint。本专项 not a new DFX Viewpoint or Perspective；任何 Availability & Resilience、Evolution、Security 或 Regulatory Perspective 仅在具体 Concern 需要时采用。

    1. 评估对象与边界¶

    Solution Outline claim
  → Hosting / Deployment Path
  → Runtime / Dependency Path
  → IT Operations Support & Management Path
  → Deployment & Operational Enablement

    Operational 在本专项中明确指 IT Operations。它不指业务运营、服务运营、客户支持流程、知识 Owner 流程、业务升级或 Operating Model。

    概念 在本专项中的作用
    Hosting / Deployment Assumption 方案需要何类候选承载、部署或交付路径；不等于最终云、本地、SaaS 或边缘选型。
    Runtime / Dependency Assumption 核心能力需要何类运行时、服务、版本、依赖、集成和资源条件。
    IT Operations Assumption 方案需要哪些最低 IT Operations 技术能力，才能被配置、变更、发现问题、支持、人工介入、停用/回退或方向性管理。

    本专项不选择最终 hosting 模型、云/私有环境/SaaS、本地或边缘方案；不设计拓扑、网络、规格、CI/CD、完整监控告警、SLO/SLA、Runbook、灾备或完整 IT Operations 模型。

    下列情况都不自动证明本专项成立：既有应用、历史生产使用、带重试的管线、业务升级路径、存在业务/产品/数据 Owner，或“cloud-based / enterprise-grade / managed”等泛称。

    2. 评估域的开发方法与原则¶

    本专项是一个可复用的 Technology Assessment Domain，不是新的核心对象、生命周期阶段或 Assessment 线。

    完成条件 在本专项中的落实
    明确评估对象 特定 Outline claim 的 hosting/deployment、runtime/dependency 与 IT Operations 技术使能路径。
    可控评估深度 只判断可信路径、关键限制与最小验证；不进入最终选型、详细部署或完整 IT Operations 设计。
    可解释的判断逻辑与结果 以三个判断面和 Supported / Conditional / Unproven / Blocked 表达，不使用平均分。
    明确证据与追溯方式 每项判断关联 Outline claim、Stakeholder、Concern、Deployment / Operational 最小 View、E0–E4 证据、限制与最小验证。
    明确决策接口与主归属 Technical Viability 判断技术路径；本专项识别条件并通过 Under What Conditions 路由；Readiness to Proceed 判断平台/支持前提；Risk & Control 判断控制与风险接受；Inception 深化实现。

    开发节奏¶

    1. 从 Solution Outline 提取 hosting、runtime、dependency 或 IT Operations 主张
2. 明确 Stakeholder Concern、系统边界和业务后果
3. 定义最少且相互不重叠的判断面
4. 为每个判断面定义调查问题、事实类型与最小证据
5. 定义 Supported / Conditional / Unproven / Blocked 的判定逻辑
6. 识别条件并通过 Under What Conditions 路由至 Readiness to Proceed、Risk & Control、Investment & Timing 或 Inception
7. 使用真实或历史场景回填；发现表达缺口时再修订本专项

    通用纪律¶

    • 证据先于结论：事实、假设、推断、条件与结论分开记录；E0–E4 表示证据强度，不替代判断状态。
    • 不从平台/部署标签倒推问题：先有 Outline claim 与 Concern，再选择 Deployment / Operational Viewpoint 与必要 Perspective。
    • 不以 IT Operations 代替业务运营：业务 Owner、人工升级或客户支持流程不构成 IT Operations 使能证据。
    • 不把跨线事项留在技术结论中：每个判断面可以识别条件与技术证据；其 materiality 由 Under What Conditions 筛选，前提可得性、控制充分性、风险接受与投入时机由相应 IA 维度形成结论。
    • 以最小充分深度止步：只取足以支持 Go / Defer / No-go 或 Inception 交接的证据。

    3. Solution Outline 输入¶

    输入 要求
    Hosting / Deployment Assumption 方案需要何类承载、部署、交付、隔离、区域或环境条件；可包含可接受的替代路径。
    Runtime / Dependency Assumption 核心能力需要的服务、运行时、版本、依赖、集成边界、资源或受支持平台条件。
    IT Operations Assumption 对配置、变更、最小问题发现/诊断、支持、人工介入、停用/回退、方向性恢复或退役的最低要求。
    Known Technical Constraints 已知的环境、平台、依赖、生命周期、变更、支持或非协商技术限制。

    Outline 只写“需要 / 应具备 / 必须遵守”的主张，不写“环境已准备”“平台可用”“运维已覆盖”或“控制已获批准”等 Assessment 结论。

    4. 结构化评价¶

    不使用打分或平均分。每个判断面分别记录技术状态、证据、已识别条件与 Inception 交接；条件的 materiality 由 Under What Conditions 筛选，再按关键路径形成专项结论。

    判断面 要评价什么
    Hosting & Deployment Path Enablement 是否存在可承载 Outline 核心能力与关键依赖的可信候选 hosting/deployment path，并能满足已知地点、环境、网络、隔离、集成或交付方向约束；不选择最终方案。
    Runtime Platform & Dependency Enablement 候选运行环境是否可能运行核心能力并接入必要依赖，涵盖运行兼容性、依赖可达性、版本/生命周期方向性约束和必要的失败/降级限制；不设计详细运行时架构。
    IT Operations Support & Management Enablement 是否存在最低 IT Operations 技术路径，使服务/依赖可被配置、变更、最小发现和诊断、支持、人工介入、停用/回退、方向性恢复或退役；不设计完整监控、告警、SLO、Runbook 或恢复机制。

    判断状态¶

    状态 含义
    Supported 已有证据支持该技术主张。
    Conditional 技术路径存在，但依赖明确外部条件或仍需补充有限证据。
    Unproven 尚无足够证据，不能据此形成可行性结论。
    Blocked 已知约束否定该主张，或必须修改 Outline / 采用替代路径。
    Not asserted / Not assessed Outline 未提出相关 hosting、runtime 或 IT Operations 主张；本次不评估，不代表技术已支持。

    E0–E4 记录“凭什么知道”，不等同于上述判断状态。

    专项结论规则¶

    任一关键判断面 = Blocked
→ 专项通常为 Blocked；除非修改 Outline 主张或采用替代路径。

无 Blocked，但存在关键 Unproven
→ 专项为 Unproven；应优先补证据。

关键路径均已验证，但存在平台、支持、控制或其他外部条件
→ 专项为 Conditional；识别条件并通过 Under What Conditions 路由至 Readiness to Proceed / Risk & Control / Investment & Timing / Inception。

全部关键判断面均为 Supported
→ 专项为 Supported。

    专项结论只表达技术路径判断，不是 Readiness to Proceed 或 Risk & Control 的跨域汇总结论。

    内容 主归属

    一句话¶

    Deployment & Operational Enablement 评估方案是否存在可信的承载、运行、依赖与最低 IT Operations 技术路径；它嵌入平台、支持与风险条件，但不选择最终部署方案，也不设计完整 IT Operations。
