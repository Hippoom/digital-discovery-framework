    解决方案级 RAID 登记册¶

    1. 用途¶

    用于记录一份版本稳定的 Solution Outline 在跨 Assessment Domain、跨 Assessment line 或 Gate 层面尚未关闭的 Risks、Assumptions、Issues、Dependencies。

    本登记册是可选的汇总 Artifact，不是新核心对象、阶段、Gate 或 Workflow。它引用各 Domain / Assessment 的源记录，不复制其详细证据，也不替代 综合评估记录卡 的跨线判断。

    仅当事项影响多个 Domain、多个 Assessment line、整体行动边界、Go / Defer / No-go、实施切片、投入时机或需要统一 Owner 和关闭条件时，才应登记。

    2. 关系与范围（必填）¶

    字段 内容
    outline [在 metadata 中链接所服务的 Solution Outline。]
    outline_version [登记册适用的版本、日期或范围标识。]
    关联 Integrated Assessment [链接对应的综合评估记录；若尚在形成中，说明当前范围。]
    登记边界 [说明哪些跨域/跨线事项纳入，哪些保留在原 Domain 或 Assessment 中。]

    3. 登记规则¶

    类型 定义 不应替代什么
    Assumption 未验证但方案或 Gate 必须成立的前提。 Domain 中完整的假设、证据和验证计划。
    Issue 已存在、正在阻塞或实质损害方案推进的事实问题。 常规待办或实现缺陷清单。
    Risk 可能发生且需要缓解、接受、转移或持续观察的负面后果。 Risk & Control 对控制充分性和残余风险接受的正式结论。
    Dependency 依赖外部平台、团队、资源、决策、供应商、环境或时间窗口的事项。 Readiness to Proceed / Investment & Timing 的详细调查记录。

    每项只指定一个主归属。其他 Assessment line 或 Domain 通过“源记录 / 交接”引用，不重复写出独立结论。

    4. 登记表¶

    RAID ID 类型 方案级条件 / 问题 源 Domain / Assessment 引用 受影响的 Outline claim 主归属与 Owner 关闭所需证据 / 决策 Gate 影响 状态 / 下一步 / 复审触发
    [RAID-001] [Assumption / Issue / Risk / Dependency] [ ] [ ] [ ] [ ] [ ] [Go 前条件 / Defer 条件 / No-go 风险 / Inception handoff] [Open / Monitoring / Closed；下一步；触发条件]

    5. 与 Gate 和 Inception 的接口¶

    情形 处理方式
    Go 前必须解决或明确接受 在 Integrated Assessment 的 Go 前条件中引用 RAID ID，并标明所需证据或有权决策。
    当前应 Defer 在 Defer / 重启条件中引用 RAID ID，并说明重启信号、责任人和复审时点。
    可能 No-go 说明导致 No-go 的具体事实、风险或不可协商约束，以及仍需谁作出决定。
    可进入 Inception 深化 说明为何不阻塞 Go、需要保留哪些约束/证据，以及 Inception 需关闭的详细设计或验证事项。

    Risk acceptance 必须由适当的 Risk & Control / Decision Authority 处理。将事项移交 Inception 不代表自动关闭 RAID。
