    协调能力（含 Agent）的定位与边界¶

    定位：仅在 Digital Discovery 判断方向需要 Agent 时，决定它应扮演什么角色，以及什么该由它做、什么不该。 关联：Reference/AI场景适配与能力边界。Agent-enabled 方向在获 Go 后进入相应的专项工程实践；该工程深化不属于 Digital Discovery。

    一、适用前提与两种定位¶

    先决条件：单一确定性能力、固定流程或普通系统已足够时，不引入 Agent；只有需要跨能力、多步骤协调、解释或受控交互时，才使用以下定位。

    决策者(常见默认) 协调者(企业场景更常见)
    谁下判断 Agent 自己拍板 Agent 编排能力,判断由能力/规则/人下
    核心动作 直接给结论 理解目标 → 拆解 → 调用能力 → 汇总 → 解释 → 交互
    适合 低风险、可容错、无明确规则的场景 高风险、要担责、规则清晰、需可解释的场景
    风险 幻觉/越权/不可解释/难追责 编排复杂、需要能力齐备

    常见误区:把 Agent 默认当"决策者",于是所有问题都往"让它自己答"上靠——结果既不可靠也不可解释。

    二、Agent 该做的六件事(协调者)¶

    1. 理解目标(用户到底要什么);
    2. 拆解问题(分成可执行的小问题);
    3. 调用能力(Rules / Workflow / ML / Optimization / GenAI);
    4. 汇总结果;
    5. 解释原因(为什么是这个结论);
    6. 与人交互(澄清、确认、呈现)。

    三、什么时候 Agent 不该"自己决策"¶

    • 高风险 / 需担责(资金、合规、安全相关)→ 判断交能力或人,Agent 只做编排与解释;
    • 规则清晰(有明确条件判断)→ 用 Rules,别让模型自由裁量;
    • 要可解释 / 可审计 → 结论要有来源与过程,不能是"模型觉得";
    • 需最优解 → 用 Optimization,而非"生成一个看起来不错的答案"。

    四、职责边界与人的分工(自动化程度)¶

    档 Agent 角色 适用
    自动执行 直接执行(低风险、可回滚) 打标、查询、草稿
    建议 + 人确认 给方案,人拍板 补货、选品、调价
    仅解释 不决策,解释他人结果 高风险结论的解释

    写操作/副作用要有确认、幂等与审计；这些属于 Agent-enabled 方向在获 Go 后需要深化的下游工程，而非 Digital Discovery 的实现设计。

    五、与"能力"的关系¶

    • Agent 是编排壳,价值来源是能力(ML / Optimization / Rules / GenAI…);
    • 所以先定能力组合,再定 Agent 角色——顺序反了会做出一个"什么都能聊、什么都不可靠"的壳。

    六、误区清单¶

    • ❌ 把 Agent 当决策者,替人拍板高风险结论;
    • ❌ 用一个 Agent 包打多个问题类型(应是"问题类型 × 能力"组合);
    • ❌ 追求"全自动",忽视"建议+人确认"这一档;
    • ❌ 只做交互壳,能力没接上(看起来聪明,结论无依据)。

    一句话：先定能力组合；仅在需要协调时再定 Agent = 协调者（编排 + 解释 + 交互）；高风险判断交给能力或人。
