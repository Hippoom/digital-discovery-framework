    Digital Discovery 治理与责任模型¶

    用途：定义 Digital Discovery 工作流背后的角色、责任、评估输入、决策权和 Gate 机制。

    关联：Digital Discovery 工作流。Workflow 说明工作如何推进；本文件说明谁在何处负责什么、谁有权作出决定。

    1. 设计原则¶

    1. 责任角色不等于组织职位。 一个角色可由不同组织、职级或多人共同承担；不要把流程绑定为“必须由产品经理/架构师/某委员会”执行。
    2. 提供评估输入不等于拥有决策权。 例如技术方对技术评估负责，但不单独决定是否投资；Sponsor 支持方向，也未必拥有正式授权。
    3. 风险与成本不是技术方独占责任。 技术、业务、运营、合规、安全、法务、财务等分别对其专业输入负责。
    4. Gate 对工件和证据作决策，不对口头方案作决策。 缺少关键输入时，应 Defer 或要求补齐，而不是以模糊共识通过。

    2. 责任角色¶

    责任角色 英文锚点 核心责任 可能的实际承担者
    业务方 Business Owner 随方向成熟逐步明确；如已确认，对业务结果、业务规则与当前范围持续负责，并确认关键业务事实与领域约束。Gate / Go 交接时须有充分、可追溯的业务责任安排 业务负责人、领域专家、运营负责人、一线代表
    解决方案牵头方 Solution Lead 组织三阶段活动；形成和协调解决方案假设；协调纲要和综合评估；组织决策包；在 Stage 1 持有机会与方向形成的工作责任 在本 Operating Model 中通常由 Digital 侧的解决方案架构师（Digital Solution Architect）承担；也可由产品、业务架构、服务设计/BA 等承担
    技术方 Technology Lead 提出能力路径；核验技术前提；形成技术评估、证据、技术风险与量级判断 技术负责人、AI/数据/平台专家、架构师、工程负责人
    关键相关职能方 Key Stakeholders 提供领域、数据、运营、财务、法务、合规、安全、采购等专业事实、约束与评估输入 数据治理、运营、财务、法务、合规、安全、采购、人力等
    投资发起方 Executive Sponsor / Sponsor 推动和支持业务机会进入探索；帮助协调优先级、资源与组织协同；对价值假设背书 高管、业务负责人、数字化负责人
    决策授权方 Decision Authority 在决策关口对投入、时机与条件作正式决定；接受或拒绝残余风险 授权高管、投资委员会、治理委员会、预算/架构授权机制

    容易混淆的两组角色¶

    不应混同 区别
    Sponsor vs Business Owner Sponsor 在 Stage 1 支持并推动机会探索、协调优先级与资源；Business Owner 随方向成熟逐步明确，并持续对业务结果、规则与范围负责。两者可由同一人承担，但不应默认等同。
    解决方案牵头方 vs 技术方 前者整合业务、方案、评估和决策材料；后者对技术路径与技术证据主责。一个人可兼任，但责任不同。
    投资发起方 vs 决策授权方 前者推动与背书；后者拥有 Go / Defer / No-go 的正式授权。小组织可为同一人，大组织通常不同。

    3. 三阶段责任模型¶

    RACI：R=负责执行（Responsible）；A=最终负责/授权（Accountable）；C=被咨询（Consulted）；I=被告知（Informed）。

    阶段/关键活动 业务方 解决方案牵头方 技术方 关键相关职能方 投资发起方 决策授权方
    Stage 1：业务机会澄清、业务结果与约束 C（如已知） A/R C C C I
    Stage 1：解决方案假设形成 C（如已知） A/R C C C I
    解决方案纲要形成 C（已确认时；否则由等效安排） A/R R C I I
    综合评估输入形成 C（已确认时；否则由等效安排） A/R（整合） R（技术） R（各专业维度） C I
    决策包编制与 Gate 建议 C（已确认时；否则由等效安排） A/R R（技术输入） C C I
    Go / Defer / No-go 决策 C R（组织与说明） C C C A/R
    Go 后交接至 Inception A/R（已确认时；或等效业务安排） A/R（交接） R（技术交接） C I I

    RACI 反映责任，不代表每个角色必须参加每次会议。参与深度应随场景风险、投入与影响范围调整。

    渐进式责任原则：Stage 1 不要求已任命 Business Owner。Solution Lead 对机会澄清与假设形成负责，Sponsor 提供支持与协调；Business Owner 可在已知时参与。随着方向进入纲要、评估与决策，业务责任及其持续对接方式逐步明确；Gate / Go 交接时，必须记录充分的业务、运营、技术与决策责任安排及持续对接路径，可由已确认的 Business Owner 或等效的书面安排实现。

    4. 综合评估的责任归属¶

    综合评估由解决方案牵头方整合；每条评估线由最接近证据和责任的人提供主输入。

    评估维度 主要负责输入（R） 整合/最终负责（A） 必须咨询（C） 决策使用
    价值与战略适配 业务方 业务方 / 投资发起方 解决方案牵头方、财务等 是否值得投入、组合位置
    解决方案适配 解决方案牵头方 解决方案牵头方 业务方、技术方 方向是否回应业务机会、范围是否合理、近期 ambition horizon 是否相符
    技术可行性 技术方 技术方 解决方案牵头方、数据/平台等 技术、数据与集成方向是否可信，技术量级与最小验证路径
    推进准备度 对应前提 Owner（业务/数据与知识/技术/管控/人员/最低运营等） 解决方案牵头方（整合） 技术方、业务方、管控职能 对下一承诺而言，前提是否具备、可补齐或不可获得
    风险与管控 对应风险 Owner（合规/法务/安全/隐私/业务风险等） 对应风险 Owner 业务方、技术方、解决方案牵头方 控制方向是否充分、哪些条件不可协商、残余风险是否可接受
    投入与时机 解决方案牵头方（汇集） 投资发起方 / 决策授权方 业务、技术、运营、财务、采购等 是否应现在承诺、资源与时间窗口、依赖顺序与 Go / Defer / No-go

    推进准备度（Readiness to Proceed）的责任分解¶

    推进准备度不是技术检查表；它回答的是：对下一承诺或 Ambition Roadmap 的近期 horizon 而言，所需前提是否已经具备，或能在承诺前现实地补齐。它至少包含：

    推进准备度维度 主输入方 例子
    业务 业务方 Owner、目标、规则/约束、关键决策权
    数据与知识 数据/知识 Owner 数据口径、知识来源、样本、更新责任、访问授权
    技术 技术方 系统、接口、能力路径、平台依赖、基本技术可行性
    管控 管控职能 合规、安全、隐私、审计、责任边界
    运营 业务/运营/产品/技术共同 基本 Owner、度量、更新、人工接管/停用路径

    最低运营前提是 Readiness to Proceed 的一个维度，不是另起一套详细运营设计。

    与投入与时机的区别：推进准备度判断前提能否在下一承诺前闭合；投入与时机判断即使前提可闭合，现在是否是正确的承诺时点和组合顺序。

    5. 决策关口（Gate）机制¶

    5.1 Gate 输入¶

    决策关口至少需要：

    - 解决方案假设：为什么探索这个方向
- 解决方案纲要：方向具体意味着什么、边界和前提是什么，以及当前 Ambition Roadmap horizon 与后续 ambition 的排序假设
- 综合评估：价值与战略适配、解决方案适配、技术可行性、推进准备度、风险与管控、投入与时机。专业职能按需要提供证据、约束、关闭行动或专业升级，但不自动构成额外评分轴。
- 建议：针对下一 investment horizon 的 Go / Defer / No-go 及理由
- 若 Defer：重启条件、责任人和复审时间/触发信号
- 责任安排：Gate / Go 交接所需的业务、运营、技术与决策责任及持续对接路径；可包含已确认的 Business Owner 或等效的书面安排

    5.2 Gate 参与与输出¶

    项 说明
    召集与材料 Owner 解决方案牵头方
    技术证据 Owner 技术方
    价值/业务结果 Owner 业务方与投资发起方
    风险/管控证据 Owner 对应关键相关职能方
    正式决策 决策授权方
    决策记录 结论、理由、残余风险、条件、责任人、时间点/触发信号

    5.3 Gate 结论的治理含义¶

    结论 治理要求
    Go 明确下一阶段范围、业务/运营/技术与决策责任的交接与持续对接路径、接受的残余风险与需在建设中闭合的事项；Business Owner 可为其中已确认的责任角色，或以等效书面安排覆盖
    Defer 明确不是“搁置”；必须记录重启条件、Owner、复审日期或外部触发信号
    No-go 记录拒绝理由、替代路线或复用结论，避免同一机会以不同包装反复进入评审

    6. 全轴衔接与反馈¶

    事件 谁触发 需要回到哪里
    Inception/Implementation 发现关键前提不成立 技术方 / 建设团队 回到解决方案纲要与综合评估；必要时重新 Gate
    上线/运营发现价值假设不成立 业务方 / 运营 Owner 回到业务机会与解决方案假设
    数据、规则、风险或外部约束变化 对应 Owner 回到推进准备度 / 风险与管控评估；判断是否 Defer、调整或停止
    新机会出现或组合优先级变化 投资发起方 / 决策授权方 回到 Gate 的投入与时机判断

    Discovery 不止发生在立项前；它是全轴的决策机制。运营和建设反馈可触发新的 Discovery，但不会把 Discovery 扩展为详细工程或运营执行。

    一句话¶

    Operating Model 通过责任角色、RACI、评估责任和 Gate 权限，确保 Discovery 的每项判断有证据 Owner、每个 Gate 有授权主体、每次 Defer 都有可追踪的重启条件。
