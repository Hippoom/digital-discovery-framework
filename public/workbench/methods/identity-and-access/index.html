    Identity and Access¶

    本方法为 Technical Viability（TV）提供一组可选调查问题，帮助判断 SO 所述 User Client(s) 方向是否存在可信的技术访问路径。这里的 User Client(s) 指 SO 为支持相关 User 行动所提出的 Client 方向，不是业务上的用户或客户主体。它是调查锚点而非已选产品或实现；本方法评估路径、依赖、限制和未知，不替 SO 选择 Client，也不进行详细身份与访问管理（IAM）设计。

    何时使用¶

    当 SO 所述 User Client(s) 涉及用户身份识别、认证、授权，或需判断既有 Client 是否能承载所需访问时，可按需使用。调查以 SO handoff 中可识别的 User Client(s) 主张为锚点，结合相关 User、Action 与 Scope；Touchpoint 作为关联场景信息，仅在其具体细节可能实质改变技术路径时深入。Location & Environment 等 Conditions 也以 SO 已识别的内容为输入；未声明的条件不自行推导为技术要求。

    调查视角¶

    无需逐项完成以下问题；只调查足以支持当前评估和下一步判断的部分。

    • 身份与认证。 现有身份来源和认证机制能否支持所述 User？既有 Client 是否已有可复用路径，或是否需要扩展？
    • Client 与访问路径。 若为既有 Client，是否能承载所需 Action 与 Scope，是否存在可信的能力扩展路径？若为新 Client，是否有可承载它的平台路径，或需要开发定制 Client？相关 Conditions 会带来什么限制或依赖？
    • 授权判断依据。 系统是否能取得足以支持所需访问范围的业务上下文或授权依据？依据尚不清楚时，记录未知和需要验证之处。

    这些是组织调查的可选视角，不是强制状态轴、成熟度等级或评分表。已有 Client 的路径与扩展能力、新 Client 的平台承载或定制路径，都根据相关 SO 主张和证据具体判断；不预设其中一种必然可行或更优。

    记录与边界¶

    记录与被评估的 SO 主张和范围相对应的事实与来源、假设、依赖、限制、未知，以及能帮助判断的最小验证。证据应说明实际支持什么、不能说明什么。路径或主张有重要变化时，指出哪些发现需要重新检查。

    本方法不规定具体产品、Client、平台、身份源、角色、权限策略、IAM 架构或实施设计；不判断控制是否充分或风险是否可接受。适用义务与控制进入 Risk & Control，业务采用、所有权和持续运营进入 Operating Viability。
