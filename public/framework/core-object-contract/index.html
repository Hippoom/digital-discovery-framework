    核心对象关系契约¶

    用途：定义 Digital Discovery 最稳定的核心对象、规范名称、单向追溯关系与语义边界。本契约是框架的核心治理内容：用于约束 Workflow、Playbook、Artifact、Reference、Assessment Domain 与后续一致性检查，但不替代任何活动方法、记录模板或 Gate 决策。

    更新频率应低。仅当核心对象的定义、关系基数、规范名称或跨对象边界发生实质变化时更新；新增技术评估域、Reference、案例、字段提示或导航链接，不应自行改变本契约。

    1. v0.1 范围¶

    本版本只定义以下四个对象：

    Business Opportunity
  → Solution Hypothesis
    → Solution Outline
      → Integrated Assessment

    本版本明确不定义：

    • Decision Package / Decision Gate；
    • solution-wide RAIDs；
    • Technology Assessment、With what、Under what conditions的详细方法；
    • Workflow、Playbook、Artifact、Reference 的详细结构；
    • 旧术语、目录、导航、Hook 或 Linter 规则。

    相邻治理结构：Ambition Roadmap 是 Solution Outline 的方向性规划组成；Decision Package / Gate 是与核心对象链相邻的治理机制。二者不在 v0.1 中增加新的核心 traceability object 或 metadata 关系。

    2. 规范对象与语义边界¶

    对象 规范中文名 核心回答 不回答
    Business Opportunity 业务机会 为什么值得探索？谁在什么情境下存在何种问题、需求或机会；希望改善什么目标动作与业务结果。 以什么解决方案、能力、技术或产品实现回应。
    Solution Hypothesis 解决方案假设 可能以什么业务或服务方向回应？为谁创造什么价值，与当前做法有何不同，初始范围和非目标是什么。 L1 Solution Archetype、能力组合、服务触点、行动边界、技术路径或投资结论。
    Solution Outline 解决方案纲要 该方向需要是什么样？优先场景、L1 Solution Archetype、能力/交互方向、行动边界、信息/行动需求、假设与约束，以及方向性的 Ambition Roadmap。 这些条件是否已具备、技术是否可行、风险是否可接受、投入是否合理或是否应通过 Gate。
    Integrated Assessment 综合评估 凭什么认为该 Outline 值得、做得了、管得住、现在可推进？针对稳定 Outline 版本形成 Value & Strategic Fit、Solution Fit、Technical Viability、Readiness to Proceed、Risk & Control、Investment & Timing 的证据与判断。 重新定义目标场景、L1 Archetype、能力、触点或行动边界。

    简记：

    BO = why explore
SH = possible direction
SO = what the solution needs to be
IA = evidence and judgement

    3. 关系与追溯规则¶

    3.1 关系基数¶

    1 Business Opportunity
  → 0..n Solution Hypotheses

1 Solution Hypothesis
  → 0..n Solution Outlines

1 Integrated Assessment record
  → exactly 1 stable Solution Outline version
    • 当前未形成可推进 SH 的 BO 可以处于 On Hold；这不是 Gate 的 Defer。
    • 当受益对象、价值机制、初始范围或服务方向发生实质变化，应回到 SH 层形成或拆分方向。
    • 当 L1 Archetype、能力/交互形态或行动边界形成实质不同的方案主张，可在同一 SH 下形成多个 SO。
    • 本契约不规定同一 SO 版本可有几份 IA Record；但每份 IA Record 必须明确其评估的 SO 版本和范围。

    3.2 规范 metadata 关系¶

    对象 必填关系 规范 metadata
    Solution Hypothesis 指向唯一来源 BO business_opportunity: "业务机会 — 简短名称"
    Solution Outline 指向唯一来源 SH solution_hypothesis: "解决方案假设 — 简短名称"
    Integrated Assessment 指向被评估的 SO 及版本 outline: "解决方案纲要 — 简短名称" + outline_version: "[版本 / 日期 / 范围标识]"

    关系由下游对象单向维护。上游对象不维护人工反向清单，避免漂移。

    4. 不可互换规则¶

    Business Opportunity ≠ Solution Hypothesis
Solution Hypothesis ≠ Solution Outline
Solution Outline ≠ Integrated Assessment

    具体而言：

    • 不能把 BO 写成预设解决方案；
    • 不能把 SH 写成 Archetype、能力架构或实现方案；
    • 不能把 SO 的“需要什么”写成“已经具备/已经可行/风险可接受”；
    • 不能把 IA 的证据与判断写回为新的 SO 定义而不明确反馈和版本变化。

    5. 文档角色与本契约的关系¶

    文档类型 受本契约约束的方式
    Workflow 说明对象如何形成、交接、回流和退出；不改变对象定义。
    Playbook 说明如何分析和形成对象；不创建平行核心对象。
    Artifact 记录对象及其规范关系；不执行流程或替代判断。
    Reference / Assessment Domain 提供某一对象或评估线的可复用方法；不升级为生命周期对象。
    Operating Model 定义对象/证据的责任与决策权；不改变对象语义。
    Method validation 可使用受控的历史或真实材料验证方法；不自动创建当前核心对象或 Gate 结论。

    6. 更新纪律¶

    更新本契约前，应明确记录：

    1. 哪个核心对象定义或关系发生变化；
    2. 为什么现有契约不足以表达；
    3. 将影响哪些 Workflow、Artifact、Reference、Operating Model 或检查规则；
    4. 是否需要迁移既有 metadata 或历史记录。

    除非以上任一项成立，不应为局部术语、专题 Reference、案例学习或技术实现细节更新本契约。

    一句话¶

    核心对象关系契约固定 Digital Discovery 的最小语义链：业务机会说明为什么探索，解决方案假设提出可能方向，解决方案纲要定义方向需要是什么样，综合评估对稳定纲要版本形成证据与判断。
