    Digital Discovery — 框架 v1¶

    本文是 Digital Discovery 的收敛版定位与边界说明；历史推理材料不属于本公开阅读路径。

    Digital Discovery 在 Inception 前形成方向与投入判断，并将建设、运行的关键条件纳入决策。它不拥有详细建设或运营执行。Agent-enabled 方向在获 Go 后进入相应专项工程实践；其他方向进入相应的产品、流程、数据、自动化、架构或工程实践。

    0. 定位与范围¶

    • 是什么：一项面向业务机会的、决策导向的数字化发现实践；比较数字、数据、流程、自动化、AI 与 Agent-enabled 等可能方向，再决定是否及何时投入。
    • 中枢：方案方向与投入判断，而非预设技术或详细工程设计。
    • 决策顺序：业务机会/问题 → 解决方案方向与能力组合 → 交互/编排/自动化方式 → 如 Agent 有合理的协调价值，再定义 Agent 角色与边界。
    • 全轴含义：覆盖投资、建设与运营所需的对齐、证据、条件和反馈意识；不替代 Inception、Implementation 或 Operations 的详细执行。
    • 纪律：本区只放通用知识，不指向具体项目（项目侧单向指向本区）。

    1. 两个正交视角¶

    过程视角（主轴） 结构视角（组成）
    回答 什么时候形成或更新判断 由什么证据、角色与方法构成
    形态 Discovery：Stage 1（澄清业务机会、形成假设）→ Stage 2（纲要与评估）→ Stage 3（Gate）→ 后续活动 → 反馈 Stakeholder Concerns、Methodology、Operating Model、Reference

    对齐原则：

    1. 组成件是常驻的，阶段给它们安排合适的介入顺序；
    2. 同一组成件在不同阶段有不同粒度，例如运营条件在 Discovery 中是可运营性判断，在 Operations 中才成为实际运行机制；
    3. Gate 是过程与 Operating Model 的交点：它使用被追溯的工件和证据，而不是口头方案。

    2. 过程视角：从机会到受治理的投入判断¶

    Digital Discovery
  Stage 1：机会澄清与方向形成
    Business Opportunity（Stage 1 工作对象）
    → 0..n Solution Hypotheses
    → 0 Hypotheses = On Hold（Stage 1 内状态）
  Stage 2：Solution Outline + Integrated Assessment
  Stage 3：Decision Gate → Go / Defer / No-go
  → Inception → Implementation → Operations
                    ↑                    │
                    └──── feedback ──────┘

[业务机会卡片 / 解决方案假设卡片：记录并追溯 Stage 1 对象，不是阶段、节点或转换]
    • Digital Discovery：形成、比较并评估方向；明确价值、边界、前提、风险、投入与时机。
    • Inception：把获 Go 的方向切片并深化为可实施方案。
    • Implementation / Operations：建设、验证、发布、运行、维护和学习。
    • 反馈：建设或运营中发现的前提变化可回到假设、纲要、评估或 Gate；这不把 Discovery 变成执行活动。

    3. 结构视角：四项常驻组成¶

    组成 作用
    Workflow 定义阶段、转换、输出与最低退出条件。见 Workflow/Digital Discovery工作流。
    Operating Model 定义角色、RACI、证据责任、决策权与责任成熟过程。见 Operating Model/Digital Discovery治理与责任模型。
    Reference 提供可复用的推理标尺、方法、模板与决策工具。
    Artifacts 业务机会卡片 与 解决方案假设卡片 等可复用记录与追溯模板；注释活动、判断和关系，是 Reference 的一部分，不是 Appendix，也不构成 Workflow 的阶段、节点或转换。

    Methodology：从问题到条件化的 Agent 判断¶

    参照系（分类标尺）：

    族 取值示例
    问题类型 Classification / Execution / Assessment / Prediction-Risk / Decision-Optimization / Generation
    作用模式 职能决策、一线赋能、数字产品/服务改造
    能力与方式 产品/流程改造、Rules、Workflow、Data、ML、Optimization、GenAI、Agent-enabled coordination

    动作流：

    框定 → 选能力 → 选择交互 / 编排 / 自动化方式
     → （如采用 Agent）定义 Agent 角色与自动化档位
     → 划边界 → 明确接入与运营条件

    指导原则：

    • 先框问题，再选技术；
    • 先定能力组合，再选择交互、编排或自动化方式；
    • Agent 是条件化的协调层，不是默认业务决策者；高风险判断交给 Rules、ML、Optimization、明确负责的人与治理控制；
    • 方案主张与其证据判断分开：Outline 说明需要什么，Assessment 判断是否具备、可接受与值得现在推进。

    4. 产出与下游接口¶

    记录/语义产出 记录什么 / 回答什么 支持什么判断或交接
    业务机会卡片 记录 Stage 1 中澄清的 Business Opportunity、探索理由与 On Hold 状态 为形成一个或多个 Hypotheses 提供可追溯的业务对象；无 Hypothesis 时记录 On Hold
    解决方案假设卡片 记录每条 Stage-1 Solution Hypothesis 及其初始边界 为 Outline 与 Assessment 提供方向输入
    Solution Outline 该方向需要什么能力、边界、前提、约束与方向性的 Ambition Roadmap 形成可评估、可决策的方向主张
    Integrated Assessment 价值与战略适配、解决方案适配、技术可行性、推进准备度、风险与管控、投入与时机是否支持推进 支持 Decision Gate
    Decision Package 应 Go、Defer 还是 No-go，以及条件 受治理的投入决定与后续交接

    下游路由：

    Go
├─ Agent-enabled direction → 相应的 Agent 专项工程、验证与运行设计实践
└─ Non-Agent direction    → 相应的产品 / 流程 / 数据 / 自动化 / 架构 / 工程实践

    5. 已确定事项与待办¶

    • 框架名称：Digital Discovery。
    • Agent：条件化的协调/编排模式，而非默认结论。
    • Discovery 的边界：做什么、为什么、是否现在投入；不拥有详细交付与运营执行。
    • 将指导原则与参照系进一步整理为独立 Reference。
    • 定义 Discovery 成效的度量方式。
    • 随实际案例完善不同下游实践的交接契约。

    一句话¶

    Digital Discovery 在 Stage 1 中澄清业务机会，并形成可比较、可验证、可治理的数字化解决方案方向；随后在投入前决定是否、何时以及在什么条件下推进。Agent 只在其协调价值被证明时成为其中一种方向。
